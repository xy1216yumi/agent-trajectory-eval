# 01 项目定义书

## 1. 一句话

以**执行轨迹**为评测对象，为"科研多源信息核对 Agent"建立四类检查点的偏离判据体系，量化诊断偏离并通过干预实验回答一个产品问题：**哪些失效值得设计人机协同交互去拦截**。

## 2. 背景与问题

多步 Agent 任务的通行评测方式只看最终结果（成功率/答案对错），存在三个盲区：

- **结果分数掩盖过程失效**：答案蒙对但中间步骤已偏离的任务被计为成功；
- **无法定位**：失败了不知道坏在感知、规划、工具还是校验环节；
- **无法指导产品设计**：不知道哪类失效"值得拦、拦得住"，人机协同功能无从下手。

## 3. 目标用户与场景

- **目标用户**：研究生（与项目作者身份一致）。典型诉求：写综述/开题时核对"某论文发表于哪年哪个会议、被引量是否过某阈值、作者是否含某人"等事实性问题。
- **场景**：科研多源信息核对 Agent。给定一个研究问题，Agent 执行 检索 → 交叉核对 → 输出结构化结论。
- **为什么选这个场景**：任务天然多步；每步有可判"偏离"的中间产物（提取的条件、计划、检索 query、引用的文献）；边界情形（信息冲突、来源缺失、应拒绝）明确且常见。

## 4. 任务模板与任务集

任务集：`tasks/tasks.json`，**v2 共 45 条** = easy 10 + medium 10 + hard 14 + edge 11
（edge：信息冲突 3、三源冲突 1、来源缺失/无法核实 4、应拒绝回答 3）。

- v1（t01–t30，30 条）：easy 10 + medium 10 + hard 5 + edge 5，事实核对型为主。
- v2 追加（t31–t45，15 条对抗任务）：v1 实测发现 kimi-k3 终态成功率高达 97.8%，
  失败样本不足以支撑干预实验的统计检验。针对实测暴露的弱点定向设计：
  ①证据与常识相悖（模拟来源与模型先验冲突，考察证据忠诚度，如 t32/t33/t41）；
  ②多跳核对（t35/t44）；③相近引用/数值陷阱（t34/t36/t42）；
  ④部分信息缺失须部分拒绝（t37）；⑤三源冲突（t38）；⑥未发生事件与诚信拒绝（t39/t40/t45）。

每条任务字段：

| 字段 | 说明 |
|---|---|
| `id` / `tier` | 编号 / 难度分层 |
| `question` | 可判定的具体研究问题 |
| `ground_truth` | 确定答案 |
| `key_conditions` | 关键条件列表（感知检查点的判据对照） |
| `required_steps` | 标准流程步骤（规划检查点的判据对照），每步标注所属检查点 |
| `expected_behavior` | 仅 edge：`refuse` / `report_conflict` |
| `evidence_facts` | mock 检索返回的证据文本（real 模式由工具返回真实检索结果） |

标准流程：明确关键条件 → 制定核对计划 → 检索来源 → 交叉核对 → 校验引用并输出结论。

## 5. 三组对照配置

| 配置 | 说明 | 预期偏离 |
|---|---|---|
| 直调 direct | 一次 LLM 调用直接出答案，无规划无校验 | 最多 |
| ReAct | 推理-行动交替，带检索/引用核验工具 | 次之 |
| 反思 reflexion | ReAct 结论后再做一轮自我批评与修正 | 最少 |

## 6. 评测指标

1. **成功率**（按配置 × 难度分层）
2. **首次偏离步数**：绝对步数 + 占核心轨迹全长百分比
3. **成本浪费比**：首次偏离之后消耗的 token / 总 token
4. **延迟**：步数与耗时

## 7. 验收标准

- [x] 偏离判据写到"别人能照着判"的程度（见 `docs/02-偏离判据手册.md`，每类含正例/反例）
- [x] 任何一条轨迹都能逐步骤回溯，数据完整可复现（JSONL + seed）
- [x] 诊断报告至少 3 条有数据支撑的关键发现
- [x] 干预实验挽救率结论成立且统计显著（McNemar p < 0.05）
- [x] 监控工具 demo：喂一条新轨迹 JSONL → 自动出诊断标签与 HTML 报告
- [x] 自动预判与人工标注的一致性可量化（Cohen's Kappa）
