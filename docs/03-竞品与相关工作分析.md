## 2. 逐个分析

**LangSmith（LangChain 官方）**：trace 记录最完善（LLM/工具调用树、token、延迟），但定位是"调试与回归测试平台"：它回答"这次调用发生了什么"，不回答"Agent 在哪一步开始走错、这类错误值不值得加人机协同"。偏离判定仍需人工逐条看 trace。

**Langfuse**：开源 counterpart，能力谱与 LangSmith 类似，优势在自部署与成本追踪；同样缺少"过程偏离"这一抽象，没有检查点判据概念。

**τ-bench（Sierra）**：强调工具-Agent-用户交互的可靠性评测，用 pass^k 度量一致性，并引入模拟用户。其度量仍是终态（数据库最终状态），无法说明失败发生在哪个环节；也不做干预实验。

**AgentBench**：8 种环境的多维能力 benchmark，产出的是模型排行榜。对环境搭建要求高，且同样是终态指标。

**WebArena**：高仿真 Web 任务环境，贡献在环境真实性；评测指标为任务完成率，无过程诊断。

## 3. 差异化定位

一句话：**观测平台记录轨迹、benchmark 打分，本项目把轨迹变成诊断结论和产品决策。**

1. **新评测对象**：不看终态看轨迹——提出"感知/规划/工具调用/结果校验"四类检查点偏离判据，把"过程失效"变成可标注、可统计的对象。
2. **新指标**：首次偏离步数（含占轨迹全长百分比）、成本浪费比——回答"错误发生多早、发现多晚、浪费多大"。
3. **可干预性评测**：不止诊断"哪里坏"，还通过配对干预实验度量"拦不拦得住"（挽救率 + McNemar 显著性），把评测结论直接映射为 2×2 人机协同决策矩阵（全自动 / 被动监控 / 检查点确认 / 自动重试+护栏）。
4. **轻量可复现**：mock 模式零依赖零成本端到端复现全部统计结论；real 模式用 LangChain 回调接真实 LLM，同一套 schema 与分析代码不变。

## 4. 局限自知

- 观测平台在工程完备性（并发、存储、可视化）上远超本项目的单文件工具；本项目不与之竞争，其诊断方法论可作为插件嫁接到 LangSmith/Langfuse 的 trace 数据上。
- benchmark 的环境真实性与任务规模更大；本项目 30 条任务用于验证方法论，结论外推需谨慎（见 `docs/04-实验设计与统计方法.md` 第 5 节）。
