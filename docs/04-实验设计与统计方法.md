# 04 实验设计与统计方法

## 1. 总体设计

- **被试对象**：3 组 Agent 配置（直调 / ReAct / 反思）× 30 条任务 = 90 条轨迹。
- **组间比较**：三组配置的成功率是**非配对**的（不同架构），只做描述性对比 + 分层（难度）拆分，不做过度推断。
- **干预实验**：**配对设计**——同一任务、同一配置的"无干预"轨迹与其"在首次偏离检查点注入纠正信息后重跑"的轨迹构成一对。配对消除了任务难度与配置差异这两个混杂因素，这是本实验设计上最关键的选择。

## 2. 统计方法（全部标准库手写实现，见 `src/analyze.py`）

### 2.1 McNemar 精确检验（干预是否有效）

配对二分类结局（成功/失败）的标准检验。对 2×2 配对表：

|  | 干预后成功 | 干预后失败 |
|---|---|---|
| **基线失败** | b（被挽救） | 仍失败 |
| **基线成功** | c（被破坏） | 均成功 |

只用 discordant pairs：`p = 2 · P(X ≥ max(b,c))`，X ~ Binomial(b+c, 0.5)。
选精确检验而非卡方近似：discordant 对数可能较小，精确检验不依赖大样本假设。

### 2.2 Bootstrap 置信区间（挽救率）

挽救率 = b / 无干预失败总数。对失败轨迹做 10000 次有放回重抽样，每次重算挽救率，取 2.5%/97.5% 分位数（百分位法）。样本量小、比例可能接近 1，Bootstrap 比正态近似（Wald）区间更稳健。

### 2.3 Spearman 等级相关 + 置换检验（偏离越晚浪费越大）

对（首次偏离步数, 偏离后消耗 token）计算 Spearman ρ（平均秩处理并列）。
p 值用**置换检验**：固定 X、打乱 Y 5000 次，统计 |ρ_perm| ≥ |ρ_obs| 的比例。
不假设正态性，适合 token 这类重尾分布；n≈50 时置换检验功效充足。

### 2.4 Cohen's Kappa（标注一致性）

衡量自动预判与人工标注的一致性，扣除随机一致：

κ = (p_o − p_e) / (1 − p_e)

标注单元 = 轨迹 × 检查点（90 × 4 = 360 个标签）。判读惯例：0.61–0.80 为"实质一致"，0.41–0.60 为"中等一致"。κ < 0.6 时应回到判据手册修订歧义条款。

### 2.5 2×2 决策矩阵的分类规则

- 偏离频率：按检查点统计首次偏离次数，高于中位数为"高频"；
- 可挽救性：按检查点分组计算干预挽救率，高于各检查点挽救率中点为"高可挽救"；
- 四象限 → 全自动 / 被动监控 / 检查点确认（人机协同）/ 自动重试+护栏。

## 3. mock 模式的角色与 token 模型假设

mock 模式是**方法验证器**：用受控概率植入偏离，验证"采集→诊断→干预→统计"管线在逻辑上自洽、统计代码正确（自动预判与植入的 ground truth 100% 一致时，说明判据规则实现无误）。

token 模型假设：prompt 随历史累积计费；偏离发生后 Agent 带着被污染的上下文继续推理，纠偏重试需重放完整上下文（重试输出又追加进上下文）。该假设方向上与真实 LLM 计费机制一致（prompt tokens 占大头且随轮次增长），但**具体数字是模拟的**。

⚠️ mock 产出的所有统计数字（成功率、挽救率、ρ、p 值）仅证明"若有此类偏离模式，管线能检出并量化"，**不构成对真实 Agent 的结论**；简历引用前必须以 real 模式重跑替换。

## 3.5 real 模式的标注方法：LLM-as-judge + 人工抽检

mock 的规则化判据依赖模拟轨迹中的结构化 `observable` 字段，对 real 轨迹（自由文本输出）
不适用。real 模式改用两级标注：

1. **LLM-as-judge**（`src/judge_real.py`）：把每条轨迹渲染成 transcript（每步的推理/输出/
   工具调用与返回），连同任务的 `key_conditions` / `required_steps` / `ground_truth` /
   `expected_behavior` 和《偏离判据手册》精简版一起发给 kimi-k3，要求输出结构化 JSON
   （四检查点标签 + 偏离理由 + 首次偏离步 + 答案正确性 + edge 行为）。
   **指标性字段（wasted_tokens、cost_waste_ratio、first_deviation_step_pct）由代码确定性
   计算，不交给 LLM**——LLM 只做定性判定，算术全部可复算。
2. **人工抽检校验**：人工以判据手册为标准独立精读 ≥12 条轨迹（覆盖三组配置与各难度层，
   含 edge），与 judge 结果计算 Cohen's Kappa；不一致处逐条复核仲裁，修正记录留档。

局限：① judge 与被评 Agent 是同一模型（kimi-k3），存在"同类错误互相放过"的风险，
人工抽检是对冲手段，但抽检覆盖率有限；② kimi-k3 仅允许 temperature=1，judge 输出
存在固有随机性（用结构化输出 + 校验重试控制）；③ judge 看不到被截断的推理全文
（轨迹中推理摘要限长），可能低估感知类偏离。

**real 实测结果（2026-09-28，kimi-k3）**：judge 与 14 条人工精读抽检的检查点标签
Kappa = 0.8453（n=56），分歧全部集中在 edge 题边界行为判定（仲裁记录见
data/annotations/adjudication_log.md）。v1（30 任务）基线失败仅 2 条，
McNemar p=0.5 不显著；按第 5 节预案追加 v2 对抗任务集（45 任务 × 3 组 = 135 条轨迹）后，
失败 11 条，干预挽救率 9/11=81.8%（Bootstrap 95% CI [54.5%, 100%]），
McNemar b=9/c=2，p=0.065——**边缘显著但未达 0.05，按"不显著即不声明"原则，
干预有效性结论降级为方向性参考**。这实证了样本量/失败基数是配对设计功效的硬约束。

## 4. 样本量与功效

- 30 条任务 × 3 组是"方法验证"规模：成功率 95% CI 半宽 ≈ ±10–18%（Wilson），只够检测大效应。
- McNemar 的功效取决于 discordant 对数：本设计约 40–50 对失败轨迹进入干预，b≈40 时即使真实挽救率仅 60%，p < 0.05 的功效也 > 95%。
- 边缘层（edge）仅 5 条/组，分层结论只做描述，不做检验。

## 5. 已知局限与应对

| 局限 | 应对 |
|---|---|
| 样本量小，成功率 CI 宽 | 报告 CI；结论只写大效应；real 模式可扩任务集 |
| v1 实测失败基数过低（kimi-k3 基线 97.8%），干预实验 McNemar 不显著 | **追加 15 条对抗任务（v2，t31–t45）定向扩大失败基数**——利用实测暴露的弱点（证据忠诚度、边界拒绝、冲突处理）设计；这是真实评测迭代中"用诊断结果反哺任务集"的正常循环，非 p-hacking：对抗题设计与检验假设在追加前已固定 |
| 对抗题中"证据与常识相悖"类的 ground_truth 与真实世界事实相反（模拟来源口径） | 任务与判据中显式标注"以检索证据为准"；judge prompt 携带 ground_truth 与 evidence_facts；仅用于考察证据忠诚度，不用于宣称模型事实错误 |
| 单一标注者，主观性 | 导出人工标注模板请第二人抽查，用 Kappa 量化一致性（已内建流程） |
| mock 数据非真实分布 | 报告显著位置声明；real 模式同 schema 无缝替换 |
| 干预"注入正确信息"是理想化操作 | 真实产品中对应"检查点确认"交互，有效性需 A/B 验证；本实验给出的是可挽救性上限 |
| 任务均为事实核对型，场景单一 | 判据手册按"条件/步骤/工具/引用"抽象，可迁移到其他检索增强型 Agent |
| 多重比较未校正 | 预设 3 个主假设（集中环节/浪费相关/干预有效），其余只做探索性描述 |
