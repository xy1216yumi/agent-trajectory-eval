# 05 PRD 节选：轨迹诊断与人机协同检查点功能

## 1. 背景

科研信息核对 Agent（面向研究生）在线上灰度中发现：任务成功率尚可，但用户投诉集中于"答案引用了不存在的文献""两个来源说法不同却直接二选一"。终态指标（成功率）无法暴露这类过程失效——答案"看起来对"但证据链已污染。需要一个以**执行轨迹**为对象的诊断能力，并把诊断结论转化为产品交互决策。

## 2. 目标用户与场景

- 直接用户：Agent 产品经理 / 算法工程师（诊断与决策）；
- 间接受益用户：研究生（更可靠的信息核对体验）。
- 核心场景：给定一批历史轨迹，回答三个问题——**哪里容易坏？坏了浪费多大？拦不拦得住？**

## 3. 能力选型

| 候选能力 | 评估 | 决策 |
|---|---|---|
| 规则化检查点判据（本 PRD 主体） | 可解释、可复核、零边际成本；覆盖四类偏离的主要模式 | **采用（v1）** |
| LLM-as-judge 逐轨迹打分 | 覆盖长尾模式，但不可复核、有成本、自身会犯错 | v2 作为规则未覆盖样本的补充，且需与人工标注做 Kappa 校验 |
| 终态奖励模型（PRM 类） | 需训练数据与训练基建，重 | 暂缓；规则体系先跑出标注数据闭环，再反哺训练 |

选型理由：v1 阶段"能照着判、能算一致性"比"覆盖更多模式"更重要；规则判据同时承担**标注规范**职能（见数据闭环）。

## 4. 新评测指标定义

| 指标 | 定义 | 产品含义 |
|---|---|---|
| 检查点偏离率 | 偏离轨迹数 / 总轨迹数（按感知/规划/工具/校验分组） | 哪里容易坏 |
| 首次偏离步数 | 绝对步数 + 占核心轨迹全长百分比 | 错误发生多早、现有监控发现多晚 |
| 成本浪费比 | 首次偏离后消耗 token / 总 token | 过程失效的金钱成本 |
| 挽救率 | 干预后转成功的失败轨迹 / 全部失败轨迹（配 Bootstrap 95% CI） | 拦不拦得住 |
| 干预净收益 | McNemar b − c，附精确检验 p 值 | 干预是否统计显著地好 |

## 5. 功能需求（核心）

1. **轨迹接入**：输入 JSONL 轨迹（LangChain 回调或 mock 生成），schema 见 `src/tracer.py`。
2. **自动预判**：按判据手册逐检查点打标，输出 `auto_labels.json`；支持导出人工标注 CSV、合并人工标注、计算 Cohen's Kappa。
3. **统计分析**：成功率分层、偏离分布、首次偏离步数分布、浪费相关性、干预显著性，输出 Markdown 报告。
4. **单轨迹诊断 demo**：`monitor.py` 输入一条轨迹 → 自包含 HTML 报告（时间线 + 偏离高亮 + 成本分析），用于评审现场演示。

## 6. Badcase 处理机制

| Badcase 类型 | 检测 | 处置流程 |
|---|---|---|
| 编造引用（V-1） | 规则：source_id ∉ 检索证据集 | 进入人工复核队列 → 确认后加入判据示例库 → 高频时触发"引用校验"护栏需求 |
| 结论与证据不符（V-2） | 规则 + 人工复核 | 同上；此类是 LLM-as-judge 补充的重点 |
| 应拒绝未拒绝（V-3） | edge 任务集回归 | 触发安全/合规评审，不得仅按普通 badcase 处理 |
| 自动预判与人工冲突 | Kappa 监控 + 冲突样本清单 | 逐条仲裁 → 修订判据手册歧义条款 → 版本号 +1 |
| 级联误判（上游偏离致下游必然报错） | 首次偏离 vs 全部偏离分开统计 | 产品决策只看首次偏离，避免高估下游环节 |

## 7. 数据闭环

```
线上轨迹采样 → 规则自动预判 → 人工抽检标注 → Kappa 一致性监控
      ↑                                            ↓
真实模式重跑 ← 判据修订/护栏上线 ← 2×2 决策矩阵 ← 统计分析与干预实验
```

- 人工标注数据沉淀为金标准集，既校验规则（Kappa），也校验未来的 LLM-as-judge / PRM；
- 干预实验结论决定下一迭代的人机协同功能优先级；
- 护栏/检查点交互上线后，用同一套指标做前后对比（A/B），形成闭环。

## 8. 2×2 人机协同决策矩阵

横轴：偏离频率（高/低）；纵轴：可挽救性（高/低）。

| | **高可挽救** | **低可挽救** |
|---|---|---|
| **高偏离频率** | **检查点确认（人机协同）**：在该环节插入轻量确认交互（"以下检索结果是否相关？"），用户一次点击换成功率大幅提升 | **自动重试 + 护栏**：人力拦不住也拦不及，投入工程护栏（引用存在性硬校验、工具白名单、超时重试） |
| **低偏离频率** | **被动监控**：打点告警，badcase 进入人工复核队列即可，不打扰用户 | **全自动**：接受残余风险，不投入 |

- 分类阈值与数据来源见 `docs/04-实验设计与统计方法.md` 2.5 节；
- 矩阵按季度用新一批轨迹重算，决策允许随数据漂移调整；
- mock 数据下的当前分类（仅示意，real 模式重跑后替换）：工具调用、结果校验 → 检查点确认；感知、规划 → 全自动/被动监控。

## 9. 非目标（Out of Scope）

- 不做通用 Agent 平台/观测后台（与 LangSmith 等的分工见 `docs/03`）；
- 不做自动修复（干预实验只度量"可挽救性上限"，修复交互另立项）；
- v1 不承诺对多模态轨迹的支持。
