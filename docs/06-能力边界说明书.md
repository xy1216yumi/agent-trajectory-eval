# 06 能力边界说明书

> 面向使用者的坦诚清单：科研信息核对 Agent 当前**能全自动做什么、必须人工做什么、出错时谁兜底**。
> 依据：30 条任务 × 3 组配置的轨迹诊断与干预实验（mock 数据下的结构性格论，real 模式重跑后校准数字）。

## 1. 分级总览

| 子任务 | 分级 | 说明 |
|---|---|---|
| 单事实核对（发表年份、作者名单、会议归属） | ✅ 可全自动 | easy 层任务在 ReAct/反思配置下最稳；建议保留引用溯源展示 |
| 双事实比较（A 是否早于 B、被引量谁高） | ✅ 可全自动（带条件） | 需强制"交叉核对来源B"步骤存在；直调配置不建议投产 |
| 数值阈值判断（被引量是否超 X，含时间口径） | ⚠️ 需人工抽检 | 时间口径是最常见的感知偏离点；结论页必须展示"口径说明"供用户一眼复核 |
| 多跳核对（≥3 个条件同时成立） | ⚠️ 需人工 | hard 层偏离率显著上升；建议拆成子任务串行确认 |
| 信息冲突（两来源说法不同） | ⚠️ 需人工 + 产品交互 | 合格行为是"并列呈现口径差异"而非二选一；冲突场景应强制弹出确认卡片 |
| 来源缺失 / 无法核实 | 🛑 需兜底 | 合格行为是"拒绝回答并说明"；检测到编造数字即为 P0 badcase |
| 应拒绝的请求（编造引用等学术不端） | 🛑 需兜底 | 硬性规则拦截，不依赖模型自觉；拒绝话术 + 合规替代建议 |

## 2. 各检查点的边界（来自 2×2 决策矩阵）

- **工具调用 / 结果校验（高频 × 高可挽救）**：值得做"检查点确认"人机协同——在检索结果返回后、结论生成前插入轻量确认。这两个环节的偏离占全部偏离的约 2/3，且干预挽救率高，是投入产出比最高的拦截点。
- **感知 / 规划（低频 × 相对低可挽救）**：全自动 + 被动监控。偏离少且多由上游输入歧义引起，打点告警即可；在 prompt 中固化"先列关键条件再行动"的模板可进一步压低。
- **反思配置的价值边界**：反思循环把成功率推向最高，但 edge 层仍有失守——**反思不能替代合规硬规则**。

## 3. 兜底机制

1. **引用存在性硬校验**：结论中的每个 source_id 必须 ∈ 当次检索证据集，否则拦截并要求重答（工程规则，零模型依赖）。
2. **edge 任务回归集**：每次模型/prompt 更新必须重跑 edge 5 题，应拒绝/应报冲突行为缺失即阻断发布。
3. **成本熔断**：单轨迹 token 超过均值 3 倍即中止并转人工——偏离越晚浪费越大，长尾轨迹几乎必然是失控轨迹。
4. **人工复核队列**：被动监控命中的 badcase 24h 内人工仲裁，结论回流判据手册。

## 4. 明确的"不做"

- 不承诺对未被任何公开来源收录的信息给出判断（拒绝即正确行为）；
- 不在无交叉核对的情况下输出"确定"结论（单来源结论必须标注置信说明）；
- 不用 mock 模式的数字对外宣传效果（仅内部方法验证；对外数字一律来自 real 模式重跑）。

## 5. 边界重估节奏

每季度或每次大版本更新后：重跑全量轨迹 → 更新决策矩阵 → 修订本说明书的分级。能力边界是**数据驱动的活文档**，不是一次性承诺。
